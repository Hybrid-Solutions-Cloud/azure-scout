Assessment Catalogue ​

Azure Scout ships 66 assessments backed by 65 rule files holding 1733 rules, of which 693 are evaluated automatically and 1040 require manual confirmation.

Run one, several, or all of them:

powershell
Invoke-AzureScout -TenantID '<guid>' -Assessment 'LandingZone'
Invoke-AzureScout -TenantID '<guid>' -Assessment 'WAF: Security','Assess: Networking'
Invoke-AzureScout -TenantID '<guid>' -Assessment 'All'
1
2
3

This page is generated

Regenerate it with scripts/Build-AssessmentCatalog.ps1. Rows and counts come from manifests/assessments.psd1 and src/assess/rules/; tests/DocsAssessmentCatalog.Tests.ps1 fails the build if the committed page and a fresh regeneration disagree. Do not hand-edit it.

40 of the 66 assessments ingest governance data and therefore need ARM Reader at the tenant-root management group to resolve fully; below that scope they degrade to an explicit Unknown rather than a false zero. They are marked Gov in the tables below. See Auth & permissions per scan type.

Manual rules are questions, not failures

A manual rule is one no collected data can decide — a process control, or a source Azure does not expose. Unanswered, it is excluded from the score rather than counted as a failure. Answered, it is scored: every run writes assessment-questions.csv, and -AssessmentAnswers feeds the answers back. See Questionnaire Answers.
