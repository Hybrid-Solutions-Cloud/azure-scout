Resource Categories ​

Every resource AzureScout discovers belongs to one of the 18 categories in Category Structure, whether or not a collector reads it. Discovery records the category on each resource (Category, and CategorySource for where it came from) in ReportCache/Discovery.json, and the React report lists resources without a collector under their category as Other discovered resources.

This page is generated

Regenerate it with scripts/Build-ResourceCategoryCatalog.ps1 from manifests/resource-categories.psd1. A test fails if this page and the map differ, or if a namespace in Azure's provider catalogue (manifests/azure-provider-types.json) has no category.

How a resource's category is decided ​

  1. Collector — if a collector reads the resource type, the category is that collector's folder under manifests/collectors/.
  2. Type — otherwise the longest entry in the type table below that is the type itself or one of its parents (for example microsoft.compute/virtualmachines/patchassessmentresults covers its softwarepatches children).
  3. Namespace — otherwise the category of the type's resource provider namespace.
  4. Fallback — a namespace Azure adds after this map was updated is filed under General and marked CategorySource = Fallback, and the discovery page counts it as uncategorized, so it is visible rather than silently misfiled.
