WAF — enumerated source for the Mission Critical Well-Architected Review ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's waf.missioncritical.yaml scores an estate against Microsoft's mission-critical workload guidance, the scope of the Mission Critical Well-Architected Review assessment. The file is written against this page only, and every rule cites an item number from the tables below.

Source ​

FieldValue
AssessmentMission Critical | Well-Architected Review (30-60 minutes, multiple choice and multiple response; question text not published)
Framework versionMission-critical workload guidance on Microsoft Learn (unversioned; the extraction date is the version)
Extraction date2026-11-25
Verification methodThe overview and all eight design-area pages below were fetched in full with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-25. The assessment landing page was fetched; its guidance page was read through a search excerpt only. Every property an automated item reads was checked against the collect.json contract in src/collect/Invoke-Collect.ps1; ARM semantics come from those existing projections and were not re-checked against a live estate.

The one thing this enumeration is NOT ​

It is not Microsoft's question list. The assessment's questions are not published. The items below are Scout's reading of the mission-critical guidance, organised by the eight design areas the overview names, and the WAF-MC-* IDs are Scout's.

Sources:

  • [OVR] Mission-critical workloads
  • [ASM] Well-Architected assessment for mission-critical workloads
  • [AD] Application design
  • [AP] Application platform
  • [DP] Data platform
  • [NC] Networking and connectivity
  • [HM] Health modeling for workloads
  • [DT] Deployment and testing
  • [SEC] Security
  • [OPS] Operational procedures

Scope: an estate, not a workload ​

Scout scans subscriptions, not one workload. An automated item therefore reports on every resource of that type in the scanned scope, and says so in its remediation text. Items that need a fact Scout cannot read (health model design, SLOs, branching policy, threat models) are Manual: they carry the evidence Scout does hold, and a person answers them.

Automated items are gated: they run only when the relevant resources exist, so an estate with none of them reports those items Not assessed rather than passed. Estate-wide "exists" items are gated on the estate having at least one scanned subscription.

One reading rests on a value Scout has not seen in a live estate: WAF-MC-DP-04 excludes SQL system databases by their System tier. Estate-wide proxies (WAF-MC-AD-02, the region count) are necessary-but-not-sufficient signals and say so in their remediation text.
