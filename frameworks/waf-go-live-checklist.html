WAF — enumerated source for the Go-Live Well-Architected Review ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's waf.golive.yaml is a production-readiness review of an Azure estate. It stands in for the Go-Live Well-Architected Review assessment, for which Scout found no more than a landing page. Every rule cites an item number from the tables below.

Source ​

FieldValue
AssessmentGo-Live | Well-Architected Review (30-60 minutes, multiple choice and multiple response; question text not published)
Framework versionAzure Well-Architected Framework design review checklists on Microsoft Learn (unversioned; the extraction date is the version)
Extraction date2026-11-25
Verification methodThe assessment landing page and the five pillar design review checklists below were fetched in full with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-25. Searches of Microsoft Learn for the assessment's title and for Azure go-live guidance returned nothing about it. Every property an automated item reads was checked against the collect.json contract in src/collect/Invoke-Collect.ps1; ARM semantics come from those existing projections and were not re-checked against a live estate.

What exists, and what this enumeration is NOT ​

Scout found nothing published about this assessment beyond its landing page. The page says the assessment helps you "holistically evaluate an Azure workload in a go-forward motion across the five tenets of the Well-Architected Framework". It names no design areas, no questions and no guidance article, and Microsoft Learn searches returned no page that describes it. The only "go-live" guidance Learn returns belongs to other products (Dynamics 365, Power Pages, SAP on Azure) and was not used.

So this enumeration is Scout's own production-readiness review, built from the five pillar design review checklists, with attention on the gates a team should clear before launch: service level objectives defined, disaster recovery tested, monitoring and alerting in place, a security baseline enforced, cost guardrails set, and a safe deployment path. Its items do not map to Microsoft's questions, a Scout score is not comparable to a Go-Live Assessment result, and the WAF-GOLIVE-* IDs are Scout's. Each item cites the checklist code it draws on.

Sources:

  • [RE] Design review checklist for Reliability (RE:01 to RE:10)
  • [SE] Design review checklist for Security (SE:01 to SE:12)
  • [CO] Design review checklist for Cost Optimization (CO:01 to CO:14)
  • [OE] Design review checklist for Operational Excellence (OE:01 to OE:11)
  • [PE] Design review checklist for Performance Efficiency (PE:01 to PE:12)

Scope: an estate, not a workload ​

Scout scans subscriptions, not one workload. An automated item reports on every resource of that type in the scanned scope. Anything that needs a fact Scout cannot read (SLOs, runbooks, rehearsals, threat models) is Manual: a person signs it off.

Automated items are gated: they run only when the relevant resources (or Advisor data, or governance data) exist, so an estate with none reports them Not assessed rather than passed. Items marked "name heuristic" match a policy assignment's display name and miss a differently named one.

Two readings rest on values Scout has not seen in a live estate: the Advisor reliability and operational-excellence category names (matched as HighAvailability or Reliability, and OperationalExcellence), and the System tier that WAF-GOLIVE-RE-06 uses to exclude SQL system databases.
