WAF — enumerated source for the Sustainability Well-Architected Review ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's waf.sustainability.yaml scores an estate against Microsoft's sustainability workload guidance, the scope of the Sustainability Well-Architected Review assessment. The file is written against this page only, and every rule cites an item number from the tables below.

Source ​

FieldValue
AssessmentSustainability | Well-Architected Review (30 minutes, multiple choice and multiple response; question text not published)
Framework versionSustainability workload guidance on Microsoft Learn (unversioned; the extraction date is the version)
Extraction date2026-11-25
Verification methodThe workload index, the design methodology, the five per-pillar recommendation pages and the sustainable AI design page below were fetched in full with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-25. The assessment landing page was also fetched. The "What is sustainability?" overview page was not read. Every property an automated item reads was checked against the collect.json contract in src/collect/Invoke-Collect.ps1; ARM semantics come from those existing projections and were not re-checked against a live estate.

The one thing this enumeration is NOT ​

It is not Microsoft's question list. The assessment's questions are not published. The items below are Scout's reading of the guidance, one item per recommendation topic (or per automatable signal within a topic), and the WAF-SUS-* IDs are Scout's.

Two notes on the source:

  • The sustainability workload index links its assessment as a24b1079-29a4-4d22-b678-376e84884f76; that page and f236012a-0070-45db-b94c-fe8de0799f38 both render as "Sustainability | Well-Architected Review". Scout cites the second, as requested.
  • Carbon emissions are not collected by Scout, so every emissions item (baseline, targets, SCI) is Manual. The cost-based items rest on Microsoft's own statement that cost is a practical proxy for sustainability.

Sources:

  • [IDX] Sustainability workload documentation
  • [MTH] Design methodology for sustainable workloads
  • [REL] Reliability recommendations
  • [SEC] Security recommendations
  • [COST] Cost Optimization recommendations
  • [OPS] Operational Excellence recommendations
  • [PERF] Performance Efficiency recommendations
  • [AI] Sustainable AI design for workloads

Scope: an estate, not a workload ​

Scout scans subscriptions, not one workload. An automated item reports on every resource of that type in the scanned scope. Idle and orphaned resources, autoscale coverage, Advisor findings and edge protections are what Scout can see; region choice, application efficiency and carbon accounting are not, and are Manual.

Automated items are gated: they run only when the relevant resources (or Advisor data, or governance data) exist, so an estate with none reports them Not assessed rather than passed. Items marked "name heuristic" match a policy assignment's display name and miss a differently named one.
