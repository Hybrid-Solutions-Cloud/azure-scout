Advisor — enumerated source for the Azure Advisor recommendations assessment ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Azure Advisor is Microsoft's own recommendation engine. It analyses resource configuration and usage telemetry and raises recommendations in five categories, each rated High, Medium or Low impact. src/assess/rules/advisor.recommendations.yaml scores what Advisor reports for the estate: it does not re-derive Advisor's findings, it counts them per category and impact, flags service-retirement notices, and checks the Advisor score. It is written against this page only, and every rule cites an item number from the tables below.

Source ​

FieldValue
Source pageIntroduction to Azure Advisor; Get Advisor recommendations in Azure Resource Graph; Advisor score; category references: Reliability, Security, Performance, Cost, Operational excellence
Framework versionAzure Advisor categories (HighAvailability, Security, Performance, Cost, OperationalExcellence) and impact levels (High, Medium, Low) as documented on Microsoft Learn on the extraction date; ARG advisorresources table with the consolidated recommendationStatus field. Advisor is not versioned per recommendation, so the extraction date is the version.
Extraction date2026-11-25
Verification methodThe overview, Resource Graph, score and category-reference pages were read with the Microsoft Learn MCP microsoft_docs_search and microsoft_docs_fetch tools on 2026-11-25. The category names were confirmed against the Advisor SDK Category enum (HighAvailability, Security, Performance, Cost, OperationalExcellence). The shape of Scout's advisor[] rows was read from src/ingest/Import-AdvisorScores.ps1 and the collection filter from src/collect/Get-ScoutRawInventory.ps1. Rules were NOT run against a live tenant for this page; the repository's own hand-off notes record a live collection that returned Advisor rows through this path.

Datasetcollect.json pathFieldsNotes
Recommendations$.advisor[] (with $.advisorAvailable)Category, Impact, ImpactedField, ImpactedValue, Subscription, ShortDescriptionProblem, ShortDescriptionSolutionFilled by Import-AdvisorScores. Category names. Advisor's API and Resource Graph call the Reliability category HighAvailability. The rules match that spelling.

Limits of the data, and the projection that would remove each ​

LimitEffect on the rulesWhat is needed
Low-impact recommendations are not collected (the collection filter keeps Medium and High)No Low-impact rule can exist; ADVISOR-GOV-02 is ManualRemove the properties.impact filter on the Advisories query in Get-ScoutRawInventory.ps1, or read Low separately.
The recommendation status is not carriedA recommendation that someone dismissed, postponed or completed still counts toward a FailAdd properties.recommendationStatus (values New, InProgress, Completed, Postponed, Dismissed; verified on the Advisor Resource Graph page) to the advisor[] row, and filter rules to New and InProgress.
The stable recommendation type id is not carriedPer-recommendation rules (for example "Create an Azure Service Health alert") cannot key on the id and would have to match textAdd properties.recommendationTypeId (a GUID per recommendation type; verified on the Resource Graph page) to the row. The category-reference pages above list each type's id, so rules can then be written per recommendation.
The recommendation's resource id is not carriedImpactedField is the resource type and ImpactedValue is the resource name, so two resources with the same name in different resource groups look alike, and a rule cannot join a recommendation to compute.virtualMachinesAdd properties.resourceMetadata.resourceId (verified on the Resource Graph page) to the row.
The recommendation subcategory is not carriedRetirement notices (ADVISOR-RE-03) are found by matching the problem text, which can miss a differently worded noticeAdd the subcategory (ServiceUpgradeAndRetirement for retirements, per the Advisor service-retirement guidance). The Resource Graph page reads it as properties.recommendationSubCategory on microsoft.advisor/metadata rows, joined to recommendations on properties.recommendationTypeId; whether the recommendation rows carry it directly is not confirmed.
Category and impact come from the recommendation row itselfIf a future Resource Graph change moves them off the recommendation row, Category and Impact would read empty and every rule would passThe Resource Graph page's samples take recommendationCategory and recommendationImpact from microsoft.advisor/metadata, joined on properties.recommendationTypeId. Scout's collected rows carry them directly today, so no change is needed now; a metadata join is the fallback.
Category-level scores may not be collectedOnly a score-below-threshold check (ADVISOR-SC-01) is possible, not "Reliability score under N"Collect the microsoft.advisor/advisorscore/category Resource Graph type (listed in the Resource Graph supported-types reference), or the REST advisorScore list that returns one entity per category.

None of these projections was run against live Resource Graph output for this page. The property names are as documented on Microsoft Learn.

The enumeration — 15 items (12 automated, 3 manual) ​

Every Advisor-backed item is gated on $.advisorAvailable, so a run that skipped Advisor reports Not assessed instead of a clean pass. A passing result means "Advisor reported nothing at this level for the subscriptions it could read", not "nothing is wrong".

How this relates to the other Scout assessments that read Advisor ​

waf.cost.yaml, waf.security.yaml, waf.performance.yaml, finops.review.yaml and caf.govern.cm.yaml each read $.advisor for one category and impact as part of a WAF pillar or FinOps score. This assessment is the complete, category-by-category view of the same rows, scored on its own framework (ADVISOR); it does not replace those pillar rules, and an Advisor finding can appear in both.
