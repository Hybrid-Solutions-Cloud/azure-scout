WAF — enumerated source for the Oracle on Azure IaaS workload assessment ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

This page enumerates the review that Microsoft publishes as Azure Well-Architected Oracle on Azure IaaS workload, for Oracle software that the customer runs and manages on Azure virtual machines. src/assess/rules/waf.oracle.yaml is written against this page only, and every rule cites an item number from the tables below.

It is not Oracle Database@Azure, the OCI-managed Exadata service in Azure datacenters (oracle.database/* resources). That service has different resources and a different responsibility split, and is out of scope for this review.

The one thing this enumeration is NOT ​

It is not Microsoft's question list. The assessment's questions are not published, and the Well-Architected Oracle IaaS workload pages (well-architected/oracle-iaas/*) now redirect to the Oracle on Azure product documentation. The items below are Scout's reading of the live Oracle-on-Azure-VM guidance, and the WAF-ORA-* IDs are Scout's. Where an item has no Oracle page behind it (WAF-ORA-CO-04, CO-05 and OE-01) it is Scout's application of the general Well-Architected pillar, and the table says so.

How Scout recognises an Oracle VM ​

ARM cannot say "this VM runs an Oracle database". The only control-plane signal Scout reads is the Azure Marketplace image: a VM built from an image whose publisher is Oracle (Oracle Linux and Oracle Database images), taken from the universal discovery index ($.discovery.Resources[*]) at Properties.storageProfile.imageReference.publisher. No Oracle-specific projection exists yet.

  • Automated items are gated on at least one such VM. An estate without one reports them Not assessed, never passed.
  • An Oracle database on Red Hat, another endorsed distribution or a custom image is invisible to the automated items, which then report Not assessed. The manual items stay answerable through the questionnaire.
  • An Oracle Linux VM that runs no Oracle software would still be scored; each automated remediation says the rule keys on the image.
  • Everything that depends on the database itself (Data Guard, RMAN, AWR sizing, licensing, ASM, Far Sync, Oracle Enterprise Manager) is manual by nature.

What is not covered ​

  • Oracle Database@Azure (oracle.database/*) — see above.
  • Oracle on VMs built from non-Oracle images — invisible to the automated items (see above).
  • Oracle RAC is not supported on Azure; the review treats Data Guard or GoldenGate as the high-availability mechanism.
  • Disk-to-VM scoping is read from the VM's own storageProfile, so a data disk attached to an Oracle-image VM is scored even if the VM is a non-database server. Disks themselves are not joined (the managed-disk projection carries no managedBy).
  • Several automated items read estate-wide data (Defender plans) and flag a subscription, not only the Oracle machines in it; the rule text says so.
