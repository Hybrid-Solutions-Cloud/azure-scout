WAF -- enumerated source for the Azure Well-Architected SaaS workload assessment ​

Enumerated 2026-11-25. Verification method and limits are stated below -- read them before quoting any coverage number from this page.

Scout's waf.saas.yaml scores the review in Microsoft's Azure Well-Architected SaaS workload assessment, which independent software vendors use to check a SaaS workload against the Well-Architected Framework. src/assess/rules/waf.saas.yaml is written against this page only, and every rule cites an item number from the tables below. Most items are organisational, so they are manual questions answered with -AssessmentAnswers; a few are automated from collected Azure data.

Source ​

FieldValue
AssessmentAzure Well-Architected SaaS workload (question text not published)
Framework versionAzure Well-Architected SaaS workload guidance on Microsoft Learn, current as of the extraction date (no published version number)
Extraction date2026-11-25
Verification methodEach source page below was fetched in full with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-25. Every property an automated item reads was checked against the collect.json contract in src/collect/Invoke-Collect.ps1.

The one thing this enumeration is NOT ​

It is not Microsoft's question list. The assessment's questions are not published. The items below are Scout-derived: Scout's reading of the design considerations and design recommendations in each SaaS design-area article, restated as questions. The SAAS-* IDs are Scout's own. A Scout score is a measure of how many of Scout's items are met; it is not the score the Microsoft assessment would give.

Sources:

  • [ASM] Assessment review tool for SaaS workloads on Azure
  • [BCM] Billing and cost management for SaaS workloads
  • [GOV] Governance for SaaS workloads
  • [RO] Resource organization for SaaS workloads
  • [IAM] Identity and access management for SaaS workloads
  • [CMP] Compute for SaaS workloads
  • [NET] Networking for SaaS workloads
  • [DAT] Data for SaaS workloads
  • [DEV] DevOps practices for SaaS workloads
  • [INC] Incident management for SaaS workloads
  • [AIS] Build an AI Strategy for your SaaS Business

Automated items are gated: they run only when the resources they judge exist, so an estate without them reports those items Not assessed rather than passed or failed. Manual items are answered with -AssessmentAnswers (see Questionnaire Answers); where collected Azure data bears on the question it is attached to the item as evidence.
