Sustainability Manager Well-Architected — enumerated source for the Microsoft Sustainability Manager Well-Architected assessment ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's msm.wellarchitected.yaml reviews an implementation of Microsoft's sustainability application against the Well-Architected for Industry guidance. It is Scout's counterpart to the Microsoft Sustainability Manager | Well-Architected Assessment, which Microsoft Learn now lists as the Microsoft Dynamics 365 Sustainability Assessment. src/assess/rules/msm.wellarchitected.yaml is written against this page only, and every rule cites an item number from the tables below. Every item is a manual question answered with -AssessmentAnswers, because Scout does not read Dataverse or Power Platform data.

Product status ​

Checked against Microsoft Learn on 2026-11-25.

  • Renamed, not retired. Microsoft Sustainability Manager has been rebranded as Dynamics 365 Sustainability. Every page in the Well-Architected set carries the note that this is a new product name only, with functionality, capabilities, licensing and service offerings unchanged. Learn's Well-Architected for Industry overview lists this same assessment as the "Microsoft Dynamics 365 Sustainability Assessment". Scout keeps the MSM- prefix and the assessment name from the catalog title, and says "Dynamics 365 Sustainability" where it cites current guidance.
  • Umbrella name. Current reference-architecture pages say Microsoft for Sustainability where older pages (and the Learn training module) say Microsoft Cloud for Sustainability.
  • Preview capabilities. The guidance marks some Scope 3 categories, the water and waste data models, Teams collaboration and data approval management as preview. MSM-CF-08 and MSM-DI-07 ask whether production depends on them.
  • Replacement guidance. The Well-Architected for Dynamics 365 Sustainability pages (design principles, design and deployment and monitoring checklists, best practices) are the current source; the groups below follow them.

The one thing this enumeration is NOT ​

The questions are Scout-derived, not Microsoft's. The assessment's question text is not published, so the items below are Scout's reading of the guidance listed above. The MSM-* IDs, and the assignment of an item to a group, are Scout's own.

Scout does not read this product's data yet. Dynamics 365 Sustainability runs on Dataverse and the Power Platform. Scout reads Azure (Resource Graph and ARM) and one Microsoft Entra policy; it does not read Dataverse settings, Power Platform environments or Microsoft Entra Conditional Access, and the collect.json contract in src/collect/Invoke-Collect.ps1 holds none of that. So every rule is manual: true with query: null: it is exported as a question by Export-ScoutAssessmentQuestion, answered with -AssessmentAnswers (see Questionnaire Answers), and stays Manual and out of the score until answered. Azure resources that sit around the solution (Synapse, storage, gateways, Application Insights) are covered by Scout's Azure assessments, not by this one.

What an automated version would need ​

Everything below needs an app registration or service principal with read-only access to the environment, a new collect section, and a gate on each rule so an environment that was not read reports Not assessed instead of Pass.

ItemsWhat would be readInterface and permission
MSM-OB-01Whether auditing is on and its retentionDataverse Web API GET [org URI]/api/data/v9.2/organizations?$select=isauditenabled,auditretentionperiodv2,isuseraccessauditenabled,useraccessauditinginterval; any user can read the configuration, changing it needs System Administrator or System Customizer
MSM-OB-01Which tables are auditedDataverse Web API GET .../EntityDefinitions?$select=LogicalName,IsAuditEnabled&$filter=IsAuditEnabled/Value eq true and IsPrivate eq false
MSM-OB-02, OB-03Data export packages to Application Insights and Data LakePower Platform admin center data export (needs a managed environment and a premium Dataverse licence); no read API was confirmed in this pass
MSM-SE-01, SE-02Security roles, business units and teamsDataverse Web API tables role, businessunit, team (not researched in this pass)
MSM-SE-03, SE-04Conditional Access and PIM for the sustainability users and adminsMicrosoft Graph v1.0 GET /identity/conditionalAccess/policies; Policy.Read.All. PIM eligibility is a separate Graph API not researched in this pass.
MSM-SE-05, OB-02Defender for Cloud plans, Application Insights export targetAzure Resource Graph and ARM, which Scout already reads
MSM-IT-01, IT-02Azure emissionsAzure carbon optimization and the Emissions Impact Dashboard (not researched in this pass)

Items about method, data quality, reporting design and organisation (most of MSM-CF, MSM-DI, MSM-EX, MSM-PC and MSM-RP) have no API behind them and stay manual in any version.
