Power Platform Adoption Assessment — enumerated question set ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's pp.adoption.yaml scores Microsoft's Power Platform Adoption Assessment, an evaluation of an organisation's current use of Power Platform. src/assess/rules/pp.adoption.yaml is written against this page only, and every rule cites an item from the tables below.

Source ​

FieldValue
AssessmentPower Platform Adoption Assessment (30 minutes, multiple choice and multiple response; question text not published)
Framework versionPower Platform adoption guidance and Center of Excellence guidance on Microsoft Learn, current; the assessment itself is unversioned and its questions are unpublished
Extraction date2026-11-25
Verification methodThe assessment page, the Power Platform guidance landing page, the adoption overview pages (strategy, plan, governance, readiness, security, operations, availability), the adoption assessment article and the adoption articles marked as read in full under Sources were fetched with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-25. The remaining adoption articles are cited from the title and one-line summary given on those overview pages. Power Platform API names in the last section were checked against the Learn permission reference and REST reference overview.

The questions are Scout-derived ​

This is not Microsoft's question list. Microsoft publishes the assessment's three areas (see the note below the tables) and neither its questions nor their numbering. The items below are Scout's reading of the Power Platform adoption guidance and Center of Excellence guidance named per row, spread across Microsoft's three areas. The PPADOPT-* identifiers are Scout's. A score from this file is Scout's questionnaire score against that reading, not the score Microsoft's assessment would return.

Scout does not read Power Platform data yet ​

Scout collects Azure Resource Manager, Resource Graph and a small set of Microsoft Graph data. It does not call the Power Platform admin APIs, so it has no inventory of environments, data policies, apps or flows. All 41 items are therefore manual: each rule has manual: true and query: null, and the answer comes from the questionnaire (Questionnaire Answers). Unanswered items show as Manual and are left out of the score; they are never counted as failures. No rule reads collect.json.

The three group names are Microsoft's: the adoption assessment article says the assessment covers "Strategy, vision and business value", "Administration, governance and support" and "Nurture and adoption". The items inside each group are Scout's.

What an automated version would need ​

Authentication is a different permission surface from the Azure Resource Manager Reader role every other Scout rule reads through: the Power Platform API takes a token for https://api.powerplatform.com/.default issued to a Microsoft Entra app registration, and the admin PowerShell module signs in as a Power Platform administrator. An automated version would therefore be opt-in, like -IncludeDevOps, and every rule reading it would be gated so "switch off" or "no access" reads Not assessed rather than "nothing is configured".

This is the assessment with the least that any API can answer. The strategy and nurture groups (PPADOPT-SV and PPADOPT-NA, 22 of 41 items) describe vision, sponsorship, training and community, which no admin API records. Only part of the administration group (PPADOPT-AG) could be answered or cross-checked from the sources above. Some of these APIs are marked preview on Learn today, so each would need its current status confirmed before a rule relied on it. The Center of Excellence Starter Kit table names above were not checked on Learn for this page; confirm them before building on them.
