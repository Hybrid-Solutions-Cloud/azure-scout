Windows 11 migration readiness — enumerated source for the Windows 11 Pro Migration Readiness Assessment ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's win11.readiness.yaml is a readiness review for moving a fleet of Windows client devices to Windows 11: planning, hardware eligibility, applications, management and update control, the security baseline, and operations. It is Scout's counterpart to Microsoft's Windows 11 Pro Migration Readiness Assessment. src/assess/rules/win11.readiness.yaml is written against this page only, and every rule cites an item number from the tables below. Every item is a manual question answered with -AssessmentAnswers, because Scout does not read client devices. Azure Arc-enabled servers and Azure virtual machines are not client devices and are never used as evidence for these items.

Product status ​

Checked against Microsoft Learn on 2026-11-25.

  • Windows 10 has reached end of support. Windows 10 version 22H2 was the final version, and support ended on 2025-10-14. Devices still on Windows 10 no longer receive free security updates; the paid Extended Security Updates (ESU) programme is the only route to updates. The migration is therefore no longer ahead of a deadline, and WIN11-PL-05 asks what has been decided for each device that remains.
  • Lifecycle of the editions. Learn states that Home, Pro, Pro for Workstations and Pro for Education editions of Windows 11 receive 24 months of support from the general availability date of a version, and Enterprise and Education editions 36 months. WIN11-PL-04 asks whether the servicing strategy allows for this.
  • Tooling. Readiness is read from Intune endpoint analytics (Work from anywhere). Windows Autopatch supports Windows 11 Pro among its editions, with licence prerequisites such as Microsoft 365 Business Premium or Windows Enterprise E3 (WIN11-MG-04).
  • Nothing is retired or renamed in the guidance used here.

The one thing this enumeration is NOT ​

The questions are Scout-derived, not Microsoft's. The assessment's question text is not published, so the items below are Scout's reading of the guidance listed above. The WIN11-* IDs, and the assignment of an item to a group, are Scout's own.

Scout does not read this product's data yet. Scout reads Azure (Resource Graph and ARM) and one Microsoft Entra policy. It does not read Intune, Configuration Manager or Windows client devices, and the collect.json contract in src/collect/Invoke-Collect.ps1 holds no client device data. Azure Arc-enabled servers (domains.hybrid.arcServers) and Azure virtual machines are servers and workloads, not the user devices this assessment is about, so they are not used as evidence. Every rule is therefore manual: true with query: null: it is exported as a question by Export-ScoutAssessmentQuestion, answered with -AssessmentAnswers (see Questionnaire Answers), and stays Manual and out of the score until answered.

What an automated version would need ​

Everything below needs a Microsoft Graph app registration with read-only application permissions and tenant admin consent, a new collect section for device data, and a gate on each rule so a tenant that was not read reports Not assessed instead of Pass. Intune data covers only devices enrolled in Intune, co-managed, or tenant attached.

ItemsWhat would be readInterface and permission
WIN11-HW-01, HW-02, HW-03Windows 11 hardware readiness for each device and the top hardware blockersMicrosoft Graph v1.0 Intune endpoint analytics: userExperienceAnalyticsWorkFromAnywhereDevice (upgradeEligibility is upgraded, unknown, notCapable or capable) and userExperienceAnalyticsWorkFromAnywhereHardwareReadinessMetric (totalDeviceCount, upgradeEligibleDeviceCount and the failed-check percentages for RAM, storage and processor cores). The read permission for these resources was not confirmed in this pass; DeviceManagementManagedDevices.Read.All is the documented read permission for the sibling managed device APIs.
WIN11-HW-07, MG-02, PL-05Operating system version, edition and join state of each deviceMicrosoft Graph v1.0 GET /deviceManagement/managedDevices (operatingSystem, osVersion, complianceState, managementAgent); DeviceManagementManagedDevices.Read.All. The Intune report DevicesWithInventory also carries OSVersion, JoinType, SkuFamily, ProcessorArchitecture and the TPM fields.
WIN11-MG-03, MG-04, MG-07Feature update policies, rings and deployment progressWindows Autopatch in Microsoft Graph: admin/windows/updates/deployments and the catalog entries, plus the policy and ring resources in beta (featureUpdatePolicy, featureUpdateRing). The feature update APIs use the beta endpoint and are subject to change.
WIN11-SC-03Conditional Access that requires compliant devices, and Intune compliance policyMicrosoft Graph v1.0 GET /identity/conditionalAccess/policies; Policy.Read.All. Compliance policy APIs were not researched in this pass.

Items about planning, applications, people and process (WIN11-PL, WIN11-AP, WIN11-OP) have no API behind them and stay manual in any version. Application compatibility results come from testing, not from an inventory call.
