App and Data Modernization — enumerated source for the App and Data Modernization Readiness Tool ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's appmod.readiness.yaml scores the readiness factors behind Microsoft's App and Data Modernization Readiness Tool. The guidance says an organization is only as ready as its people, infrastructure, development processes, data management, application estate and operations. This page lists the items Scout asks, and every rule in that file cites an item number from the tables below.

Source ​

FieldValue
AssessmentApp and Data Modernization Readiness Tool (30 minutes, multiple choice and multiple response; question text not published)
Framework versionMicrosoft Azure App Modernization Guidance on Microsoft Learn, current at the extraction date. Not versioned by Microsoft
Extraction date2026-11-25
Verification methodThe assessment landing page and the guidance home, "Are you ready for application and data modernization?", maturity model, "Make an inventory and collect data", "Identity, security, and compliance best practices" and "The 6 Rs" pages were fetched in full with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-25. Every collect.json property an automated item reads was checked against the header contract in src/collect/Invoke-Collect.ps1.

The one thing this enumeration is NOT ​

It is not Microsoft's question list. The assessment's questions are not published. The items below are Scout's reading of the readiness guidance, mainly the "Are you ready for application and data modernization?" page, whose sections (organizational maturity, infrastructure, process, data management, application estate, AI adoption and operations) set the areas used here. The APPMOD-* IDs are Scout's.

The guidance also describes four maturity categories (traditional foundations, emerging pioneers, agile innovators, digital champions). Scout asks whether the organization knows which it is in but does not assign one, because the category depends on business readiness that Azure data cannot show. The score is the share of items met.

Sources:

  • [READY] Are you ready for application and data modernization?
  • [MAT] Application modernization maturity model
  • [INVN] Make an inventory and collect data
  • [PLAN6] The 6 Rs of application modernization
  • [LAUNCH] Identity, security, and compliance best practices

How the items are answered ​

Most items are questions about how the organization works, which no Azure API can read. They are manual rules: Scout lists them in assessment-questions.csv (or Export-ScoutAssessmentQuestion), and a person answers Yes, Partial, No or N/A. See Questionnaire answers. Where collected Azure data bears on a question, it is attached to the item as evidence, but the answer still decides the score. Items marked ✅ are automated and gated: they run only when the resources they read exist (or the data source was collected), so an estate without them reports the item Not assessed, never Passed or Failed, and an answer file cannot override them.

Eleven of the 62 items can be judged from Azure or Entra data, each only on the signal it names. Five need data that is not always collected: Azure DevOps repositories and pipelines need -IncludeDevOps, the policy assignment item needs the Azure Policy read, the diagnostic coverage item needs the coverage measurement, and the multifactor item needs Microsoft Entra Conditional Access to have been read (Policy.Read.All and a reader role; it reads Not assessed under -Scope ArmOnly or when Graph refuses). Resources Scout found (virtual machines, SQL servers, Application Insights and so on) are attached to some questions as evidence of the Azure part of the estate only. On-premises applications, source hosts other than Azure DevOps, the rest of Microsoft Entra (single sign-on, hybrid identity, audit logs) and the organizational questions are not visible to Scout and are left to the person answering.
