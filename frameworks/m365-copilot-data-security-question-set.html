Microsoft 365 Copilot data security — enumerated source for the Data Security for Copilot for Microsoft 365 assessment ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's m365.copilot.datasecurity.yaml is a readiness review of the data-security work that comes before and alongside a Microsoft 365 Copilot deployment: finding and fixing oversharing, labelling and protecting data, putting guardrails around Copilot, auditing its use and meeting AI regulations. It is Scout's counterpart to Microsoft's Data Security for Copilot for Microsoft 365 assessment. src/assess/rules/m365.copilot.datasecurity.yaml is written against this page only, and every rule cites an item number from the tables below. Every item is a manual question answered with -AssessmentAnswers, because Scout does not read Microsoft 365 data.

Product status ​

Checked against Microsoft Learn on 2026-11-25.

  • Renamed, not retired. The assessment still carries the old name "Copilot for Microsoft 365". Current Learn guidance calls the product Microsoft 365 Copilot, and the deployment blueprint and Purview DLP pages say Microsoft Copilot. The items apply to the product under its current name.
  • A feature in the guidance is retiring. Restricted SharePoint Search is retiring: Learn states that from 2026-07-31 new enablement is blocked, and points to Restricted Content Discovery for controlling discoverability. M365CP-RO-05 asks how an existing allow list is being retired.
  • Renamed DLP location. The Purview DLP policy location that governs Copilot is titled "Microsoft Copilot, Copilot Chat, and Copilot Cowork" on current pages. M365CP-GR-01 to GR-03 use it. Learn's Purview service description lists the sensitivity-label condition (keep labelled files and emails out of Copilot) as included in Microsoft 365 E5 licensing and not in E3, and prompt protection as available to all Copilot users.
  • Current structure. Microsoft's blueprint has three pillars: remediate oversharing, set up guardrails, meet regulations. The groups below follow it, with separate groups for sensitivity labels, audit and agents.

The one thing this enumeration is NOT ​

The questions are Scout-derived, not Microsoft's. The assessment's question text is not published, so the items below are Scout's reading of the guidance listed above. The M365CP-* IDs, and the assignment of an item to a group, are Scout's own.

Scout does not read this product's data yet. Scout reads Azure (Resource Graph and ARM) and one Microsoft Entra policy. It does not call Microsoft Graph for sensitivity labels, SharePoint or Purview, and the collect.json contract in src/collect/Invoke-Collect.ps1 holds no Conditional Access, label, sharing, audit or DLP data. The only Graph-backed field, domains.identity.externalIdentitiesPolicy, answers none of these items. So every rule is manual: true with query: null: it is exported as a question by Export-ScoutAssessmentQuestion, answered with -AssessmentAnswers (see Questionnaire Answers), and stays Manual and out of the score until answered. Items marked in the table as needing Entra data are the first that an automated version could take over.

What an automated version would need ​

Everything below needs a Microsoft Graph app registration with read-only application permissions and tenant admin consent, a new collect section for Microsoft 365 data, and a gate on each rule (an "available" flag, the way governance.budgetsAvailable works) so a tenant that was not read reports Not assessed instead of Pass.

ItemsWhat would be readInterface and permission
M365CP-SL-01, SL-02Sensitivity labels defined and publishedMicrosoft Graph beta GET /security/informationProtection/sensitivityLabels; application permission InformationProtectionPolicy.Read.All (delegated InformationProtectionPolicy.Read). Beta APIs are not supported in production.
M365CP-RO-09Tenant sharing level, domain restriction mode, guest resharingMicrosoft Graph v1.0 GET /admin/sharepoint/settings (sharingCapability, sharingDomainRestrictionMode, isResharingByExternalUsersEnabled); SharePointTenantSettings.Read.All
M365CP-RO-02, RO-03, RO-06, RO-07, RO-08, SL-04Site-level oversharing: too many users, Everyone except external users, Anyone and organisation-wide links, labelled sitesSharePoint Online PowerShell (Microsoft.Online.SharePoint.PowerShell 16.0.25409 or later): Start-SPODataAccessGovernanceInsight (needs a SharePoint Advanced Management licence) and the data access governance report cmdlets. No Graph equivalent was found on Learn.
M365CP-RO-04, RO-05Restricted Content Discovery per site; delegationSharePoint Online PowerShell: Get-SPOSite property RestrictContentOrgWideSearch, Get-SPOTenant property DelegateRestrictedContentDiscoverabilityManagement, Start-SPORestrictedContentDiscoverabilityReport
M365CP-GR-05, GR-06Conditional Access policies (MFA, legacy authentication block, risk policies)Microsoft Graph v1.0 GET /identity/conditionalAccess/policies; Policy.Read.All. PIM eligibility and access review definitions are separate Graph APIs that were not researched in this pass.
M365CP-GR-07Device enrolment and complianceMicrosoft Graph v1.0 GET /deviceManagement/managedDevices; DeviceManagementManagedDevices.Read.All

M365CP-AU-05, AG-03Copilot interaction historyMicrosoft Graph v1.0 GET /copilot/users/{id}/interactionHistory/getAllEnterpriseInteractions; application permission AiEnterpriseInteraction.Read.All; needs a Copilot licence, and excludes Copilot Studio agent interactions
M365CP-GR-01 to GR-04, AU-02, AU-03, RG-01DLP policies on the Copilot location, retention policies, insider risk and Compliance ManagerSecurity & Compliance PowerShell (Connect-IPPSSession from the Exchange Online PowerShell module). Cmdlet names for these policies were not verified in this pass, and no Graph read API for DLP policy was found.

Items about organisation, training and rollout (M365CP-RG-02 to RG-05, RO-01, RO-10, RO-11) have no API behind them and stay manual in any version.
