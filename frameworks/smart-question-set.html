CAF Migrate readiness — enumerated source (formerly the Strategic Migration Assessment) ​

Source: https://learn.microsoft.com/azure/cloud-adoption-framework/plan/ and https://learn.microsoft.com/azure/cloud-adoption-framework/migrate/plan-migration (CAF Plan and CAF Migrate, every page named in the tables below) Framework version: Not versioned by Microsoft — CAF Plan and CAF Migrate are living documentation with no published release number. Treat the extraction date below as the version. Extracted: 2026-11-24 Verification method: Manual read of each CAF Plan and CAF Migrate page cited in the tables below, on the extraction date. The retired SMART tool's own question text was never published and cannot be checked — see the warning below.

Enumerated 2026-11-24. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Why this page changed ​

Microsoft deletes the Strategic Migration Assessment and Readiness Tool (SMART) in January 2027 (https://learn.microsoft.com/assessments/Strategic-Migration-Assessment/). It was a 15-minute multiple-choice readiness questionnaire listed under Plan in the Cloud Adoption Framework's tools and templates, whose description named its subject areas: "business planning, training, security, and governance."

Scout's assessment of this name was never a copy of SMART — Microsoft did not publish SMART's questions, so Scout enumerated the CAF content SMART drew on. That content still exists. This page now enumerates it directly, from CAF Plan and CAF Migrate, and extends it to cover the whole migration sequence: plan, prepare, execute, optimise, decommission.

The SMART-* identifiers are kept, unchanged, for the items that existed before the re-base, so questionnaire answer files already saved against them keep working. New items continue the same scheme. The assessment itself is now named CAF: Migrate readiness, and Microsoft: SMART Migration and SMART remain accepted as aliases.

The audit's DQ12 records why this file exists: "Writing rules against a framework you have not enumerated is how waf.storage.yaml happened" — a rule file scoring a WAF pillar that does not exist. smart.migration.yaml is written against this enumeration and nothing else, and every rule in it cites an item number from the tables below.

⚠️ What this is not. Microsoft's SMART question text and numbering were never published — SMART was delivered only as an interactive assessment, and the identifiers below are Scout's, not Microsoft's. This enumeration is the CAF content a migration-readiness review rests on, not a transcription of the retired tool. Any coverage percentage published against this file must say so.

Product name. Microsoft's Azure Migrate documentation now calls the product Azure Catalyst. The Azure resource types are unchanged (microsoft.migrate/*), so Scout's queries still match. Where the tables say "Azure Migrate", read either name.

One source is a product page, not CAF. SMART-C6 (public network access on a migrate project) has no current CAF source. It is checked against the product guide https://learn.microsoft.com/azure/migrate/how-to-use-azure-migrate-with-private-endpoints, which also says the project may need to allow traffic from all networks. That is why Scout asks the question and shows evidence instead of scoring it Fail.

Shelf life. Microsoft is actively rewriting CAF pages (see the audit's §8 currency warnings). Re-verify before quoting, and re-date this page when you do.

All sources are under https://learn.microsoft.com/azure/cloud-adoption-framework/. "Evidence" says what Scout reads. Manual items are questions for the customer; a tool reading ARM cannot evidence whether a business case was agreed.

What this means for the rule file ​

There are 49 items. 18 are automated — a tool reading ARM can evidence them. 31 are manual because the answer is an agreement, a plan, a sign-off or a test result that lives outside Azure. smart.migration.yaml marks those manual: true with the item cited, so they appear in the report as questions for the customer rather than silently disappearing, and they are answerable from a questionnaire answers file whether or not any migration data was collected. That is the difference between "18 of 49 automatable" and a fabricated score of 100%.

When no Azure Migrate project, discovery site or migration service was collected, the rule file's requires block holds the whole set at Unknown rather than scoring it, because zero unassessed projects and no project at all are the same number and opposite findings. That covers the automated items outside C as well (D to F, I, K), so an estate with no migration data gets no automated score from this assessment; the manual items stay answerable from a questionnaire answers file. A manual item that has evidence (C5, C6, K3) shows it, and never scores its absence.
