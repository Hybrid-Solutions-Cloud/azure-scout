Analytics Journey Tracker — enumerated source for the Analytics Journey Tracker assessment ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's analytics.journey.yaml scores the data and analytics capabilities Microsoft's Analytics Journey Tracker evaluates. The tracker is a data strategy accelerator: it measures capabilities and processes across several pillars at five maturity levels, then helps build use cases, initiatives and a roadmap. This page lists the items Scout asks, and every rule in that file cites an item number from the tables below.

Source ​

FieldValue

Not versioned by Microsoft

Verification methodThe assessment landing page, the CAF unified data platform overview, planning, architecture, data governance, Fabric governance and operational standards pages, the Fabric adoption roadmap maturity-levels page and the CAF cloud-scale analytics URL were fetched in full with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-25. The Fabric adoption roadmap data culture, executive sponsorship and overview pages and the Microsoft Purview data governance overview were read through microsoft_docs_search excerpts the same day. Every collect.json property an automated item reads was checked against the header contract in src/collect/Invoke-Collect.ps1.

The one thing this enumeration is NOT ​

It is not Microsoft's question list, and the pillars are not Microsoft's. The tracker's landing page names five maturity levels, Initial (non-existent, unpredictable, reactive), Evolving (frequently reactive, ad hoc), Acceptable (well characterised, more proactive than reactive), Advanced (measured and controlled, predictable) and Optimized (stable, flexible, fed back through improvement loops), but it does not name its pillars or publish its questions. The seven areas below, and the ANLJT-* IDs, are Scout's grouping of the published guidance.

Scout does not assign a maturity level. Each item is a practice the guidance describes, written so it can be answered Yes, Partial or No; Yes and No sit near the Acceptable-or-better and Initial-or-Evolving ends of the five levels. The score is the share of items met.

The Cloud Adoption Framework's former cloud-scale analytics scenario no longer exists: its URL now serves the Unified data platform guidance, which is the source used here, together with the Fabric adoption roadmap's maturity-level topics. Microsoft has also stopped creating new Microsoft Purview data governance accounts and is consolidating data governance into Fabric, so Purview accounts are attached as evidence and never required.

How the items are answered ​

Most items are questions about how the organization works, which no Azure API can read. They are manual rules: Scout lists them in assessment-questions.csv (or Export-ScoutAssessmentQuestion), and a person answers Yes, Partial, No or N/A. See Questionnaire answers. Where collected Azure data bears on a question, it is attached to the item as evidence, but the answer still decides the score. Items marked ✅ are automated and gated: they run only when the resources they read exist (or the data source was collected), so an estate without them reports the item Not assessed, never Passed or Failed, and an answer file cannot override them.

Only five of the 52 items can be judged from Azure data: public network access, private endpoints and managed identity on Azure Data Factory, and public network access and managed virtual network on Azure Synapse. Each runs only when the estate has those resources. Fabric capacities, Purview accounts, Databricks workspaces, reservations and AI accounts are attached to some questions as evidence only. Scout does not read Fabric tenant settings, workspaces, OneLake security, lineage or Purview content, because none is an Azure Resource Manager resource.
