Power Platform Well-Architected — enumerated source for the Power Platform Well-Architected assessment ​

Enumerated 2026-11-25. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's pp.wellarchitected.yaml scores Microsoft's Power Platform Well-Architected assessment, which examines the reliability, security, operational excellence, performance efficiency and user experience of a workload design. src/assess/rules/pp.wellarchitected.yaml is written against this page only, and every rule cites an item from the tables below.

Source ​

FieldValue
AssessmentPower Platform Well-Architected (60 minutes, multiple choice and multiple response; question text not published)
Framework versionPower Platform Well-Architected pillar checklists on Microsoft Learn, current (Reliability RE:01-08, Security SE:01-10, Operational Excellence OE:01-11, Performance Efficiency PE:01-10, Experience Optimization XO:01-10); no version number is published
Extraction date2026-11-25
Verification methodThe assessment page, the pillars page and each of the five pillar checklist pages were fetched in full with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-25, and every code and recommendation below was copied from those tables. Per-item guidance links are the checklist's own links. The individual guidance articles were not each read in full. Power Platform API names in the last section were checked against the Learn permission reference and REST reference overview.

The questions are Scout-derived ​

This is not Microsoft's question list. Microsoft does not publish the assessment's questions. What it does publish is the pillar checklists, each recommendation carrying a code (RE:01, SE:01 and so on). Scout turns each checklist recommendation into one yes/no statement, so the PPWAF-* identifiers carry Microsoft's codes (PPWAF-RE-01 is Microsoft's RE:01) but the wording of every question is Scout's paraphrase, and the assessment's own multiple-choice questions may split, merge or reorder them. A score from this file says how the workload sits against the published checklist. It is not the score Microsoft's assessment would return.

Scout does not read Power Platform data yet ​

Scout collects Azure Resource Manager, Resource Graph and a small set of Microsoft Graph data. It does not call the Power Platform admin APIs, so it has no inventory of environments, data policies, apps or flows. All 49 items are therefore manual: each rule has manual: true and query: null, and the answer comes from the questionnaire (Questionnaire Answers). Unanswered items show as Manual and are left out of the score; they are never counted as failures. Entra Conditional Access, which SE:05 touches, is read by Scout's Entra inventory but is not part of the assessment collection, so it cannot be used as evidence either.

Sources, the pillar checklists:

  • [RE] Recommendation checklist for Reliability
  • [SE] Recommendation checklist for Security
  • [OE] Recommendation checklist for Operational Excellence
  • [PE] Recommendation checklist for Performance Efficiency
  • [XO] Design review checklist for Experience Optimization

What an automated version would need ​

Authentication is a different permission surface from the Azure Resource Manager Reader role every other Scout rule reads through: the Power Platform API takes a token for https://api.powerplatform.com/.default issued to a Microsoft Entra app registration, and the admin PowerShell module signs in as a Power Platform administrator. An automated version would therefore be opt-in, like -IncludeDevOps, and every rule reading it would be gated so "switch off" or "no access" reads Not assessed rather than "nothing is configured".

These are the sources that would answer the most items, with the names as they appear on Microsoft Learn today. A source is only useful where it can show a setting or an inventory. Items about team practice (OE-01, OE-03, SE-02, XO-01 to XO-09 and most of PE) will stay questionnaire items whatever is collected.
