WAF — enumerated source for the Azure Virtual Desktop workload assessment (AVD in Azure) ​

Enumerated 2026-11-24. Verification method and limits are stated below — read them before quoting any coverage number from this page.

Scout's waf.avd.yaml scores Azure Virtual Desktop deployed on Azure Local (see waf-avd-workload-checklist.md). This page enumerates the companion review for AVD running in Azure, which is the scope of Microsoft's Azure Well-Architected Azure Virtual Desktop workload assessment. src/assess/rules/waf.avd.azure.yaml is written against this page only, and every rule cites an item number from the tables below.

Source ​

FieldValue
AssessmentAzure Well-Architected Azure Virtual Desktop workload (60 minutes, multiple choice; question text not published)
Framework versionAzure Virtual Desktop guidance on Microsoft Learn, current; ARM Microsoft.DesktopVirtualization latest GA API 2025-10-10
Extraction date2026-11-24
Verification methodEach source page below was fetched in full with the Microsoft Learn MCP microsoft_docs_fetch tool on 2026-11-24. Every ARM property an automated item reads was checked against the Microsoft.DesktopVirtualization ARM template reference or the SDK reference.

The one thing this enumeration is NOT ​

It is not Microsoft's question list. The assessment's questions are not published, and the WAF AVD design-area pages (well-architected/azure-virtual-desktop/*) now redirect to AVD product pages or return 404. The items below are Scout's reading of the live AVD guidance, and the WAF-AVDAZ-* IDs are Scout's.

Sources:

  • [SEC] Security recommendations for Azure Virtual Desktop
  • [BCDR] Multiregion business continuity for Azure Virtual Desktop
  • [SVOC] Start VM on Connect
  • [AUTO] Autoscale scaling plans
  • [VAL] Configure a validation environment
  • [SAU] Scheduled Agent Updates
  • [PL] Private Link with Azure Virtual Desktop
  • [INS] Azure Virtual Desktop Insights
  • [FSL] Storage options for FSLogix profile containers
  • [DEP] Deploy Azure Virtual Desktop

Automated items are gated: they run only when the relevant AVD resources exist, so an estate with no AVD reports them Not assessed. Joins to virtual machines use the session host's resourceId; session hosts on Azure Local are not Azure VMs, so they drop out of those items rather than being mis-scored.
